# 知诉 · 12345 AI 问数工作台

面向面试任务的可运行演示：在服务端权限边界内，通过对话探索工单、办理事件、回访与业务知识，生成受控的动态分析界面。

**当前没有配置模型密钥。默认启动的是明确标注的规则演示模式。真实模型工具调用代码已实现，并用模拟模型响应验证协议，但自由问数质量仍需接入真实模型后验收。**

## 快速运行

需要 Python 3.11+。在本目录执行：

```sh
python -m venv .venv
# Windows
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python app.py
# macOS / Linux
# .venv/bin/pip install -r requirements.txt
# .venv/bin/python app.py
```

打开 http://127.0.0.1:8000 ，选择演示身份。默认不需要访问码。若设置 `DEMO_ACCESS_CODE`，需先输入访问码再选择身份。

如果网络无法下载依赖，配置你信任的 PyPI 镜像；不要关闭证书校验。

## 任务要求与实现

| 任务要求 | 实现 | 如何验证 |
|---|---|---|
| 按权限受限查询 | 市、区、部门、经办人四种演示身份；授权工单及其关联记录装入独立内存查询数据库 | 换身份问相同问题，再尝试跨区、跨部门查询 |
| 灵活查询多样数据 | Schema 工具、通用只读 SQL 工具、文档关键词检索工具；支持多表关联、聚合和窗口函数 | 接入模型后测试未预设问题，查看实际工具调用和 SQL |
| 多样化页面 | Agent 输出页面 JSON，由前端渲染指标卡、排名图、折线图、表格、时间线、文档 | 比较概览、趋势、回访、单工单追踪的展示形式 |
| 多轮对话 | 服务端保存当前身份的最近对话；模型继承明确上下文；换身份开启新会话 | 提问后追问“只看东城区”“按月展开” |
| 可解释与可核查 | 执行工具、SQL、行数、耗时、指标定义和查询审计 | 展开结果底部“查询依据与执行记录” |

**通用 SQL 工具是一个受限数据访问能力，不是“查询销售额”一类预设业务接口。** 模型可自由组合当前授权 Schema 中的字段和关系。规则演示模式使用有限模板，不能作为真实 Agent 灵活性已达标的证据。

## 数据多样性

固定快照：**2026-11-19 12:00**。固定随机种子，可重复生成；无需下载、创建或持久化业务数据库。全部是合成数据，区名、人员、规则与背景不对应真实城市业务。

| 数据表 | 记录数 | 类型和用途 |
|---|---:|---|
| tickets | 24,000 | 工单主数据、32类主题、正文、时间、状态、渠道、区域 |
| events | 80,511 | 一对多时序事件，用于流转与耗时分析 |
| feedback | 18,241 | 回访评分、满意度、文本意见 |
| departments | 8 | 职责与业务类别 |
| service_targets | 8 | 分类办理时限和模拟目标 |
| knowledge_docs | 17 | 业务指引、回访规范、区域协调纪要 |
| daily_context | 2,920 | 八区每日合成降雨、周末背景 |
| district_profiles | 8 | 人口、街道数量和面积 |

共 **125,713 条记录**，涵盖八个区域、八个业务类别、四个受理渠道、近一年记录。模拟了11月东城区噪声诉求集中、不同类别办理时长差异、逾期与回访评分的统计关联。不能从合成数据推断现实规律。

数据多样性不仅是记录数量，还包括：实体记录、事件序列、评分、长文本、规则文档和背景数据。当前提供的是八张表，不是八个独立在线数据源；尚未实现任意数据库接入、Excel上传或向量语义检索。

## 接入真实模型

服务使用兼容 Chat Completions 的工具调用协议，需要模型支持 `tools` 和 `tool_calls`。

| 环境变量 | 作用 |
|---|---|
| LLM_API_KEY | 模型服务密钥。留空启用规则演示 |
| LLM_BASE_URL | API前缀，默认 `https://api.openai.com/v1`；代码追加 `/chat/completions` |
| LLM_MODEL | 模型名称，默认 `gpt-4.1-mini`，可替换为服务商支持的模型 |
| SECRET_KEY | Cookie签名密钥；Render Blueprint自动生成。生产必须固定设置 |
| DEMO_ACCESS_CODE | 可选的演示入口访问码，建议公开链接时设置 |
| STATE_DIR | 对话与审计SQLite存储目录，默认 `runtime/` |

`.env.example` 仅是配置示例，程序不会自动加载 `.env`。不要把真实密钥提交到仓库。服务端发送给模型的内容包括当前授权 Schema、问题、最近对话与工具结果；使用真实数据前应确认模型服务的数据处理政策。

### 阿里云百炼

在Render的Environment中设置：

```text
LLM_API_KEY=你保存的完整百炼API Key
LLM_BASE_URL=百炼API Key页面左侧显示的OpenAI兼容Base URL
LLM_MODEL=你准备使用的模型Code
```

优先从百炼控制台复制对应业务空间的地址，例如 `https://<workspace-id>.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`，不要选择右侧的Anthropic兼容地址，也不要在此变量后添加 `/chat/completions`。密钥、地址及可用模型需要属于匹配的地域和业务空间。模型还必须支持工具调用；有免费额度不代表已经验证本项目的Agent兼容性。

免费额度演示建议保留“免费额度用完即停”，并设置 `DEMO_ACCESS_CODE` 防止公开链接被任意调用。完整密钥仅存储在服务端环境变量中。

工具：

1. `inspect_schema`：返回授权表结构、关联、范围与指标口径。
2. `query_data`：执行单条只读SQLite查询，可连接全部授权表。
3. `search_documents`：对授权文档进行关键词检索，返回编号、标题与正文。

最多7轮模型响应、14次工具调用；每次SQL有约2秒与操作指令预算、最多200行40列。模型只预览前40行时会收到明确标记，统计应由SQL聚合完成。模型异常、非法JSON或工具循环超限会明确报错，不悄悄切换为规则模式伪造结果。

## 部署到 Render

无需额外前端构建，前后端由一个Web Service提供。仓库根目录已包含Render配置；实际部署需在Render控制台连接此仓库。

### 推荐：Render Blueprint

1. 将**本目录内容**作为Git仓库根目录上传GitHub。不要上传 `runtime/`、`.env`、虚拟环境和密钥。
2. 在Render选择 **New → Blueprint**，连接仓库，使用 `render.yaml`。
3. 选择适合的实例方案；配置模型密钥、模型地址和模型名称。暂时不接模型时，`LLM_API_KEY` 留空。
4. 配置 `DEMO_ACCESS_CODE`，作为面试演示链接的入口访问码。
5. 部署后访问页面，并确认右上角模式提示和 `/healthz`。

### 手工创建 Web Service

- Runtime：Python
- Build Command：`pip install -r requirements.txt`
- Start Command：`gunicorn app:app --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 180`
- Health Check Path：`/healthz`
- 环境变量按上表配置，并固定设置足够长的随机 `SECRET_KEY`。

如果上传的是父目录，Render的Root Directory需设置为实际项目目录。不要同时使用不同工作目录中的同名 `app.py`。

此版本每次启动重新生成同一份模拟业务数据，因此Render磁盘不持久化也能恢复业务演示。**对话和审计默认保存在实例本地磁盘，重启或重新部署可能丢失。** 要持久化需使用持久磁盘设置 `STATE_DIR`，或将状态存储迁移至PostgreSQL。单worker配置用于保持进程内限流和任务锁一致；多实例扩展前需迁移到Redis等共享存储。

部署步骤参考：[Render官方Flask部署文档](https://render.com/docs/deploy-flask)。实例休眠、计费等以你部署时Render控制台为准。

## 权限、安全与边界

- 用户身份来自服务端签名会话，不接受聊天请求中的 `role` 来决定权限。
- 浏览器里的身份切换是**合成数据演示入口**，不是生产身份认证。真实接入需要SSO、组织人员映射及管理员授权。
- 当前演示四类身份可自由选择；访问码用于控制演示入口，不区分各角色的真实登录凭据。
- 查询沙箱只有授权行，不存在“模型漏写WHERE就查全库”的路径。事件、回访和区域背景随范围隔离。
- 市民姓名、手机号、详细住址等字段未进入分析模型；当前演示证明敏感字段不提供，不演示按角色解密查看。
- SQLite授权器限制表与函数；拒绝写入、PRAGMA、ATTACH、加载扩展、内部表与高开销查询。
- 前端将所有模型和数据库文本作为纯文本；不执行模型生成HTML/JS，图表使用白名单组件。
- 会话Cookie设为HttpOnly、SameSite；Render启用Secure。写请求需要CSRF Token。
- 对话按会话和身份隔离；审计仅返回当前身份记录。每个会话保留16条消息，状态保留约7天，审计最多保留约10,000条。
- 结果导出仅导出本次返回行，不是全量导出；CSV对公式起始字符进行防护。
- 当前不是生产级通用数据平台：未提供真实身份登录、持久化分布式会话、异步队列、连接器、向量检索和模型调用费用计量。

## 验证

```sh
python -m unittest -v test_system
node --check static/app.js
```

可选前端DOM集成测试：需要Node.js 20+，先在另一个终端以**无模型密钥、无访问码**模式运行 `python app.py`，再执行 `npm install` 和 `npm run test:ui`。只用于本地开发测试，Render运行不需要Node依赖。

11项后端测试涵盖四种权限及关联数据、恶意SQL、查询资源上限、多源关联、数据完整性、演示追问、真实Agent工具协议的模拟测试、非法模型返回、认证/CSRF、完整API链路和访问码。

本地验证通过上述测试及静态JavaScript语法检查。另外使用临时Happy DOM测试环境，对实际HTTP服务验证了页面初始化、角色登录、概览与图表DOM、提问、查询依据、八类数据目录、身份切换和越权空结果。**DOM测试不包含视觉布局验证。自动化浏览器工具连接失败，未完成视觉截图和真实浏览器交互验收；未配置模型，未完成真实模型的准确率与延迟测试；未实际部署Render。**

面试前建议逐项执行 `DEMO.md` 中的验收问题，尤其是接入模型后的未预设问题与权限攻击测试。
